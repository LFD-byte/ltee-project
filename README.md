# LTEE Project

Variant calling on LTEE E. coli samples

Author: Huifa Li ([ORCID 0009-0009-5806-385X](https://orcid.org/0009-0009-5806-385X))

## Reproduce the results

You need [Pixi](https://pixi.prefix.dev/latest/) and an internet connection.
Then, from this folder:

```bash
pixi install          # builds the exact environment recorded in pixi.lock
pixi run reproduce    # downloads the raw data and rebuilds every result
```

`pixi run reproduce` must work on a fresh clone of this repository. A GitHub
Action (`.github/workflows/reproduce.yml`) checks that on every push.

## What is where

| Folder | What goes in it | Rule |
|--------|-----------------|------|
| `data/raw/` | Data exactly as you received it | Read-only. Never edit; download it with a script. Not committed. |
| `data/processed/` | Data derived from raw data | Regenerated by code. Not committed. |
| `metadata/` | Sample sheet, data sources, checksums, data dictionary | Small text files, committed. |
| `scripts/` | Code you write (Python, shell) | Committed. |
| `config/` | Parameters for the analysis or workflow | Committed. |
| `workflow/` | Snakemake and Nextflow pipelines | Committed. |
| `notebooks/` | Jupyter notebooks for exploration | Committed, outputs cleared or small. |
| `reports/` | Quarto documents that turn results into a report | Source committed, rendered HTML not. |
| `results/` | Figures, tables, logs made by the code | Regenerated. Not committed. |
| `docs/` | Longer documentation | Committed. |
| `envs/` | Conda `environment.yml` exports, for people without Pixi | Generated from `pixi.toml`. |
| `containers/` | Dockerfile and Apptainer recipe | Committed. |

Each folder has its own `README.md` with more detail.

## Data availability

Raw reads are in the NCBI Sequence Read Archive under BioProject
[PRJNA295606](https://www.ncbi.nlm.nih.gov/bioproject/PRJNA295606)
(runs SRR2589044, SRR2584863, SRR2584866; Tenaillon et al. 2016,
<https://doi.org/10.1038/nature18959>). The trimmed, subsampled reads used
here are the Data Carpentry Genomics Curriculum Example Data on figshare,
<https://doi.org/10.6084/m9.figshare.7726454> (CC0). The reference genome is
*E. coli* B str. REL606, NCBI assembly
[GCA_000017985.1](https://www.ncbi.nlm.nih.gov/datasets/genome/GCA_000017985.1/)
(ASM1798v1).

Download links and the providers' md5 checksums are in
`metadata/sources.tsv`, SHA-256 checksums of every raw file in
`metadata/checksums.sha256`, and the sample sheet and data dictionary in
`metadata/samples.tsv` and `metadata/README.md`. `python
scripts/download_data.py` downloads and verifies the raw data; all derived
data in `data/processed/` and `results/` is regenerated from it by the code
in this repository (MIT license).

## Container

Build the Linux x86-64 pipeline environment from the same `pixi.lock`:

```bash
docker build --platform linux/amd64 -f containers/Dockerfile \
  --build-arg ENV_NAME=pipeline -t ltee-project:0.1.0 .
docker run --rm --platform linux/amd64 ltee-project:0.1.0 samtools --version
docker run --rm --platform linux/amd64 ltee-project:0.1.0 fastqc --version
docker run --rm --platform linux/amd64 ltee-project:0.1.0 bwa
```

`bwa` without arguments prints its version and usage, then exits nonzero.
The Dockerfile installs the locked environment in a Pixi build stage and
copies it, at its original path, into Ubuntu. The entrypoint activates the
environment; Pixi itself is not needed in the final image. Build for
`linux/amd64` on Apple silicon because the lock supports `linux-64`, not
`linux-aarch64`. Keep data, results, `.pixi/` and image archives out of the
build context with `.dockerignore`.

Run the lesson's variant-calling command from the project root:

```bash
docker run --rm --platform linux/amd64 -v "$PWD":/work -w /work ltee-project:0.1.0 \
  bash scripts/run_variant_calling.sh
python3 scripts/check_variants.py
```

For the complete project reproduction (data checksum verification, FastQC,
MultiQC, variant calling, Quarto report and variant verification):

```bash
docker run --rm --platform linux/amd64 -v "$PWD":/work -w /work ltee-project:0.1.0 \
  bash scripts/reproduce.sh
```

`pixi run reproduce` uses this same script in the pipeline environment.
On Linux, add `--user "$(id -u):$(id -g)" --env HOME=/tmp` to `docker run`
so generated files belong to you. Results are in `results/`; the report is
`reports/ltee-report.html`. The `Containers` GitHub Actions workflow builds
and runs the complete container workflow on every push and pull request.
The `Reproduce` workflow checks the native Pixi path independently.

### Missing bind mount and optional Apptainer

```bash
docker run --rm --platform linux/amd64 ltee-project:0.1.0 bash scripts/run_variant_calling.sh
```

Without `-v "$PWD":/work`, this must exit 127 with
`bash: scripts/run_variant_calling.sh: No such file or directory`.
The image contains software; project files are supplied by the bind mount.
CI checks this expected failure.

Apptainer is optional and Linux-only; it is not run on this macOS machine.
On Linux with Docker, use:

```bash
apptainer build containers/ltee-project.sif docker-daemon://ltee-project:0.1.0
apptainer exec containers/ltee-project.sif samtools --version
apptainer run containers/ltee-project.sif bash scripts/run_variant_calling.sh
```

After registry publication, `containers/apptainer.def` provides the recipe
using `ghcr.io/lfd-byte/ltee-project:0.1.0` for a cluster without Docker.
